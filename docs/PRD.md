# PRD: Note-a-Style (노터스타일)

> Product Requirements Document v2.0
> 최종 업데이트: 2026-02-28
> MVP 개발 완료 단계 -- Phase 재정의

---

## 1. 제품 개요

### 1.1 제품명
**Note-a-Style (노터스타일)** -- "시술 기록의 신"

### 1.2 한줄 요약
뷰티샵(헤어/네일/피부/두피관리)의 **시술 기록 관리와 AI 포트폴리오 생성** 멀티테넌트 SaaS 플랫폼

### 1.3 핵심 포지셔닝
기존 CRM(핸드SOS, 헤어짱, 스마일패드, 뷰카 등) 위에 얹어지는 **프리미엄 애드온**.
예약관리가 아닌 **시술 내용 기록과 AI 포트폴리오**에 집중.

### 1.4 Value Chain
```
원장님 (매장 운영) ←→ 디자이너님 (시술 기록) ←→ 고객님 (서비스 수혜) ←→ 기자재 사장님 (자재 공급)
```

## 2. 시장 배경 및 Pain Point

### 2.1 산업 규모
- 국내 헤어샵(미용실) 총 **112,464개**, 생활서비스업종 중 두 번째(**21.5%**)
- 헤어샵 시장 연 매출 규모 약 **6조 원 이상**, 기자재 시장 약 **6,000억 원**
- 분기당 신규 미용실 오픈 약 **1,500개 이상**
- K-뷰티는 세계적 영향력을 보유하지만 디지털/전산화가 크게 부족

### 2.2 현재 문제점

#### 획일화된 솔루션
기존 솔루션(핸드SOS, 헤어짱, 스마일패드, 뷰카, 공비서, 토스플레이스 등)은 **예약관리에만 집중**.
관리 업무, 홍보/마케팅, 기자재 소싱을 모두 별도로 관리 → 비용 증가.

#### 악순환 구조
```
과도한 마케팅 비용 → 서비스 단가 상승 → 디자이너 급여 절감
→ 기자재 비용 절감 → 소비자 피해 → 더 자극적인 마케팅 필요 → (반복)
```

#### 구체적 문제
| 문제 | 설명 |
|------|------|
| 비전문적 고객관리 | 기억이나 메모에 의존하는 고객 히스토리 관리 |
| 실력 검증 어려움 | 디자이너 역량을 객관적으로 판단할 수 없음 |
| 깜깜이 기자재 시장 | 가격 정보 부족, 합리적 구매 어려움 |
| "샵 유목민" 현상 | 만족스러운 매장을 찾지 못해 떠도는 소비자 |

### 2.3 경쟁사 분석

| 솔루션 | 특징 | 한계 |
|--------|------|------|
| **핸드SOS** | 고객관리, 예약관리, 매출관리, 네이버예약 연동 | 시술 기록/포트폴리오 없음 |
| **헤어짱** | 고객/영업 정보 분석 | 예약 중심, AI 없음 |
| **스마일패드** | 무료, 30가지+ 기능 | 범용적, 시술 기록 특화 아님 |
| **뷰카** | 모바일+PC, 자동문자 | 예약 중심 |
| **토스 플레이스** | 결제 연동, 매장 관리 | 뷰티 특화 아닌 범용 |

**노터스타일의 차별점**: 이들 모두가 예약관리에 집중하는 반면, 노터스타일은 **시술 기록 + AI 포트폴리오**라는 미개척 영역에 집중.

## 4. 제품 비전 -- AI 핵심 기능

### 4.1 AI 페이스 스왑 (초상권 보호 포트폴리오)
- **기술**: Replicate API (`codeplugtech/face-swap` 모델)
- **현재 구현**: 매장별 페이스 모델 라이브러리 관리, 배치 생성, 결과 선택 → 포트폴리오 자동 등록
- **비용**: 건당 ~$0.0027

### 4.2 AI 스타일 노트 (사진 위 어노테이션)
- **현재 구현**: 사진 위 핀 노트 (좌표 기반), 최대 10개, 드래그 위치 조정
- **가치**: 시각적/누적적 시술 관리

### 4.3 AI 음성 메모 구조화
- **기술**: OpenAI Whisper + GPT-4o Structured Output
- **현재 구현**: 녹음 → 텍스트 변환 → 구조화된 시술 데이터 자동 생성
- **프라이버시**: 음성 파일은 변환 후 즉시 삭제

### 4.4 AI 스타일러 (Phase 2+)
- 고객에게 다양한 스타일 제안과 미리보기 제공

### 4.5 AI 상담 챗봇 (Phase 3)
- 24/7 자동 고객 응대

## 6. 핵심 사용자 플로우

### 6.1 시술 기록 입력 (예약 기반)

```
예약 생성 (/reservation)
  └→ 고객 검색/선택 → 날짜/시간 → 서비스 선택 → 저장
      └→ 예약 보드 (/tasks) 에서 확인
          └→ "시술 시작" 버튼
              └→ 시술 레코드 자동 생성 (예약 정보 복사)
                  └→ 사진 촬영 (before/during/after)
                      └→ 상세 입력 (제품, 부위, 메모)
                          └→ 저장

[직접 시술 생성] (/treatments/new)
  └→ 고객 선택 → 서비스 → 제품/부위/시간 → 저장 → 사진 촬영

[음성 메모] VoiceMemo 컴포넌트
  └→ 녹음 30초 → Whisper → GPT-4o → 자동 폼 채우기 → 저장
```

### 6.2 AI 페이스 스왑 플로우

```
시술 사진 확인 (/treatments/[id])
  └→ "AI 페이스 스왑" 버튼
      └→ 페이스 모델 라이브러리에서 소스 선택
          └→ 배치 생성 (복수 결과)
              └→ 결과 목록에서 마음에 드는 것 선택
                  └→ 포트폴리오 자동 등록 + 원본/AI 변환 비교
```

### 6.3 포트폴리오 & Explore 플로우

```
[소스 A] 시술 상세 → "포트폴리오 추가" → 갤러리 등록
[소스 B] 페이스 스왑 결과 선택 → 자동 등록
[소스 C] (Phase 2) Instagram 연동 → 게시물 선택

포트폴리오 갤러리 (/portfolio)
  └→ 공개/비공개 토글 (owner/admin만)
      └→ SNS 공유 (Web Share API)

Explore 페이지 (/explore)
  └→ 공개 포트폴리오 검색 (shop_type 필터)
      └→ 디자이너 프로필 (/explore/designer/[memberId])
          └→ 경력, 자격증, SNS, 포트폴리오 갤러리
```

### 6.4 매장 온보딩 플로우

```
회원가입 (/login)
  └→ Email 또는 Kakao OAuth
      └→ user_profiles 자동 생성
          └→ 온보딩 (/onboarding)
              ├→ [옵션 A] 매장 생성
              │   └→ 매장명, 유형, 주소 → 기본 서비스 자동 시딩
              │       └→ 초대 링크 생성 → 멤버 초대
              │
              └→ [옵션 B] 초대 수락
                  └→ 초대 코드/링크 입력
                      └→ 매장 멤버로 합류 (지정된 역할)
```

## 7. 비기능 요구사항

### 7.1 성능
- 페이지 로딩: 1초 이내
- 사진 업로드: 10MB 이하, 3초 이내
- 음성 메모 처리: 30초 녹음 → 10초 이내 구조화

### 7.2 플랫폼
- **PWA**: 모바일/태블릿 최적화 (max-width: 480px)
- 다크/라이트 모드 지원
- 브라우저: Chrome, Safari (iOS/Android), Samsung Internet

### 7.3 인증/보안 (구현 완료)
- **Supabase Auth**: Email + Kakao OAuth
- **3계층 인증**: withShopAuth (매장), requireAuth (글로벌), requireAdmin (관리자)
- **역할 기반 접근**: owner > admin > designer > assistant
- **API 보안**: Zod 입력 검증, rate limiting (AI API 10/min)
- **매장 간 데이터 격리**: shop_id 기반 + withShopAuth

### 7.4 확장성 (구현 완료)
- **멀티매장**: 사용자 1명이 여러 매장에 가입 가능 (ShopContext)
